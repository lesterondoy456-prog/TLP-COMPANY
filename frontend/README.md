# SalesPort ERP demo

React login, Dashboard, and Reports with a Node.js backend. Business figures and orders are sample data. SQL Server connection settings are available for the `cas` database.

## Run locally

Install Node.js 22 or later. Open two terminals inside `ERP System`.

Terminal 1 — backend:

```powershell
cd backend
npm install
npm run dev
```

Terminal 2 — frontend:

```powershell
cd frontend
npm install
npm run dev
```

Open **http://127.0.0.1:5188**. Click **Use demo workspace**, or sign in with:

- Email: `demo@salesport.app`
- Password: `Demo2026!`

## Where to edit

```text
ERP System/
  backend/
    server.js           Server startup and SQL Server connection check
    Api/ClientApi.js    All backend API routes
    data.js             Sample dashboard data
    components/auth.js  Login and session handling
    package.json
    .env.example
  frontend/
    src/
      pages/            Login.jsx, Dashboard.jsx, and Reports.jsx
      components/       Sidebar, revenue chart, and icons
      styles/           Page styles and animations
      App.jsx           Login state and page transitions
      main.jsx          React entry point
    public/             Favicon
    index.html
    vite.config.js      Local API proxy
    package.json
```

React calls `/api/...` directly. Vite forwards these requests to the backend during development. `backend/Api/ClientApi.js` handles the routes, checks sessions using `components/auth.js`, and returns sample dashboard data from `data.js`.

Dashboard and Reports share a fade-and-slide transition. The theme button switches between light and dark mode and remembers the selection on this browser.

## SQL Server

Copy `backend/.env.example` to `backend/.env`. Set `DB_SERVER`, `DB_NAME=cas`, `DB_USER`, and `DB_PASSWORD` using a SQL Server login that can access the database.

If using a TCP port, put the host only in `DB_SERVER` and the SQL Server TCP port in `DB_PORT`. Named instances such as `localhost\MSSQLSERVER01` require SQL Server Browser for discovery. The runner does not create databases or change SQL Server services.

`server.js` logs connection success or failure. Check **http://127.0.0.1:5189/api/health** for `database.status`. Login and dashboard currently use the sample account/data regardless of database configuration; they do not read business records from `cas` yet.

`node_modules`, `package-lock.json`, and `dist` are dependency/build files generated by npm and Vite.

## Build and run

Inside `frontend`:

```powershell
npm run build
npm start
```

Stop the development backend first so port 5189 is available. Open **http://127.0.0.1:5189**. The Node server serves the built frontend and the API together.

To retain demo sessions after restarting the backend, copy `backend/.env.example` to `backend/.env` and set a random `SESSION_SECRET` of at least 32 characters. Without it, restarting the backend clears existing sessions.

This is a local design prototype with public demo credentials, not a production account system.
